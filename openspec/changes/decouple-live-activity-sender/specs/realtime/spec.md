## ADDED Requirements

### Requirement: 잠금화면 Live Activity 발송은 ingest 처리 체인과 분리되어 순서와 지연을 보장한다

잠금화면 Live Activity push 는 크롤러 스냅샷이 저장되는 즉시 독립적으로 발송되어야 하며(MUST), 같은 요청의 다른 후처리(실시간 스트림 브로드캐스트, 캐시 갱신, 워치·폰 사일런트 푸시 팬아웃)가 늦어져도 발송이 함께 늦어지거나 누락되어서는 안 된다(MUST NOT).

경기별 발송은 직렬화되어야 하며(MUST), 이미 발송한 상태보다 먼저 관측된(오래된) 상태는 나중에 처리되더라도 발송되어서는 안 된다(MUST NOT). 발송되는 갱신의 시각 표식은 경기별로 항상 증가해야 한다(MUST).

볼카운트성 갱신이 최소 간격에 걸려 미뤄진 경우, 그 시점의 최신 상태는 다음 스냅샷이 도착하지 않아도 간격 경과 후 발송되어야 한다(MUST).

시스템은 발송 시도마다 결과 사유(발송·heartbeat·동일 상태 스킵·코얼레싱 스킵·오래된 상태 스킵·토큰 없음·직렬화 실패)와 스냅샷 저장부터 발송까지의 지연을 기록해야 한다(MUST).

#### Scenario: 오래된 상태는 뒤늦게 처리돼도 발송되지 않는다

- **GIVEN** 같은 경기의 스냅샷 A(1:4, 6회초 시작)와 그 뒤의 스냅샷 B(2:4)가 연달아 저장되고
- **WHEN** B 의 발송이 A 보다 먼저 완료된 뒤 A 의 발송 차례가 오면
- **THEN** A 는 오래된 상태로 판정되어 발송되지 않고, 잠금화면 카드는 2:4 를 유지한다

#### Scenario: 후처리 지연과 무관하게 발송된다

- **GIVEN** 스냅샷 저장 뒤 사일런트 푸시 팬아웃이나 스트림 브로드캐스트가 수십 초 걸리는 상황에서
- **WHEN** 이닝 교대·투수 교체 등 주요 변화가 포함된 스냅샷이 저장되면
- **THEN** Live Activity push 는 그 후처리를 기다리지 않고 수 초 내에 발송된다

#### Scenario: 코얼레싱으로 미뤄진 마지막 투구가 자동 발송된다

- **GIVEN** 직전 발송 후 20초가 지나지 않아 볼카운트 갱신이 미뤄진 상태에서
- **WHEN** 이후 20초 동안 새 스냅샷이 도착하지 않으면
- **THEN** 미뤄졌던 최신 볼카운트가 간격 경과 시점에 발송된다

#### Scenario: 발송 결과가 사유와 지연과 함께 기록된다

- **GIVEN** 경기 중 스냅샷이 저장될 때마다
- **WHEN** Live Activity 발송이 시도되면
- **THEN** 로그에 경기 식별자, 결과 사유, 발송 성공 수, 저장→발송 지연이 한 줄로 남아 로그만으로 누락·지연·순서를 검증할 수 있다

### Requirement: 잠금화면 Live Activity heartbeat 는 스냅샷 도착과 무관하게 타이머로 유지된다

시스템은 잠금화면 Live Activity 를 구독한 토큰이 있는 진행 중 경기에 대해, 마지막 발송으로부터 60초가 지나면 스냅샷 도착 여부와 관계없이 같은 상태를 새 stale-date 로 재발송해야 한다(MUST). 이 요구는 "동일 상태 스냅샷이 반복 도착할 때만 heartbeat 를 재전송한다" 는 종전 조항을 대체한다.

heartbeat 는 데이터 파이프라인이 살아 있는 동안에만 유지되어야 한다(MUST). 해당 경기의 마지막 스냅샷 저장이 일정 시간(10분)을 넘겨 끊긴 경우 heartbeat 를 중단해 카드가 stale 표시로 떨어지도록 해야 한다(MUST). 경기가 종료되면 heartbeat 를 보내지 않는다(MUST NOT).

백엔드가 복수 프로세스로 실행될 때 한 경기의 heartbeat 는 한 프로세스만 발송해야 한다(MUST). 조정 저장소를 사용할 수 없는 경우에는 heartbeat 를 생략한다.

#### Scenario: 이닝 교대 공백에도 카드가 stale 로 떨어지지 않는다

- **GIVEN** 이닝 교대·투수 교체로 3분간 새 스냅샷이 도착하지 않는 상황에서
- **WHEN** 마지막 발송으로부터 60초가 지나면
- **THEN** 같은 상태가 새 stale-date 로 재발송되어 잠금화면 카드에 "동기화 지연" 이 표시되지 않는다

#### Scenario: 파이프라인이 멈추면 heartbeat 도 멈춘다

- **GIVEN** 크롤러 또는 저장 경로 장애로 한 경기의 스냅샷이 10분 이상 저장되지 않은 상태에서
- **WHEN** heartbeat 주기가 돌아오면
- **THEN** 재발송하지 않고, 카드는 마지막 stale-date 경과 후 "동기화 지연" 을 표시한다

#### Scenario: 복수 프로세스에서 heartbeat 가 한 번만 나간다

- **GIVEN** 백엔드 프로세스 2개가 같은 경기의 heartbeat 조건을 동시에 만족한 상태에서
- **WHEN** 두 프로세스가 같은 주기에 발송을 시도하면
- **THEN** 경기별 조정 락을 획득한 프로세스만 발송하고 다른 프로세스는 건너뛴다
