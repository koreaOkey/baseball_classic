# push-delivery

## ADDED Requirements

### Requirement: 푸시 발송 실패 원인 기록
백엔드는 APNs 푸시(일반·Live Activity·표시형) 발송이 네트워크 호출 전에 실패하더라도(인증 토큰
생성 실패, 클라이언트 초기화 실패 등) 그 원인을 로그로 남겨야 한다(SHALL). 병렬 발송 결과에
예외가 섞여 있으면 개수와 첫 예외를 요약해 기록한다. 반복되는 같은 실패의 상세 스택은 스로틀한다.

#### Scenario: 서명 키 오류
- **Given** APNs 서명 키 설정이 유효한 키가 아니다
- **When** Live Activity 업데이트를 발송한다
- **Then** 발송은 실패로 집계되고 원인이 경고 로그에 남는다
- **And** 같은 원인의 상세 스택은 60초에 한 번만 기록한다

#### Scenario: 병렬 발송 중 예외
- **Given** 토큰 3개 중 2개의 발송이 예외로 끝났다
- **Then** "2/3 sends raised <예외 타입>: <메시지>" 형태의 요약 경고가 남는다

#### Scenario: 정상 발송
- **Given** 모든 발송이 성공 또는 정상 실패(응답 코드)로 끝났다
- **Then** 요약 경고는 남기지 않는다
