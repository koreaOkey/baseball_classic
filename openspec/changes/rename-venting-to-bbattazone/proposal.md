# rename-venting-to-bbattazone — 분풀이 모드 사용자 노출 명칭 "빠따존" 전환

## Why

분풀이 모드의 사용자 노출 명칭을 "빠따존"으로 리브랜딩한다. 내부 코드명
venting(클래스·패키지·API·DB·푸시 kind)은 앱 이름 "야구봄" vs 코드명 BaseHaptic과
같은 패턴으로 그대로 유지한다 — 구버전 앱 호환(kind=venting_loss, OPEN_VENTING),
지표 연속성(venting_event 등), 리네임 churn을 피하기 위함.

## What Changes

- **명칭 원칙**: 빠따존 = 장소·모드 명칭, 분풀이 = 행위 표현(유지).
  "분풀이 완료!"·"직접 지목한 분풀이 대상"만 행위 표현으로 남긴다.
- **💢 표기 원칙**: 빠따존이 제목·배지로 단독 등장하는 곳만 "💢 빠따존"
  (룸 배지, 대상선택 화면 제목, 워치 페이지, What's New 제목).
  문장 성분·버튼·리딩 아이콘(이모지 포함)이 이미 있는 UI(설정 행, 홈카드 헤더,
  패배 팝업 제목, 테스트 버튼)에는 이모지 없이 텍스트만.
- **카피 매핑 (iOS·Android 동일)**:
  - 설정 토글·홈 피처 가이드 스텝: "분풀이 모드" → "빠따존"
  - 대상선택 화면 제목: "분풀이 모드" → "💢 빠따존", 룸 배지: "분풀이 룸" → "💢 빠따존"
  - 패배 팝업: "분풀이 모드로 진입하시겠습니까?" → "빠따존에 입장하시겠습니까?",
    버튼 "분풀이 하러 가기" → "빠따존 가기"
  - 홈카드: "분풀이 한번 해볼까요?" → "빠따존 한번 가볼까요?",
    CTA "분풀이 하러 가기" → "빠따존 가기"
  - 대상선택 버튼: "분풀이 시작하기" → "빠따존 입장하기",
    "워치로 분풀이 시작하기" → "워치로 빠따존 열기"
  - 워치 핸드오프: "워치에서 분풀이를 시작하세요" → "워치에서 빠따존에 입장하세요",
    "분풀이 룸이 열렸어요" → "빠따존이 열렸어요"
  - What's New 제목: "분풀이 모드가 생겼어요" → "💢 빠따존이 생겼어요"
  - watchOS·Wear OS 선택 페이지: "💢 분풀이" → "💢 빠따존"
  - 백엔드 패배 유도 푸시 본문(다크, 플래그 OFF): "분풀이 방에서 오늘 경기 풀고
    가세요." → "빠따존에서 오늘 스트레스 풀고 가세요." (제목의 💢 유지, 본문 이모지 없음)
  - DEBUG 워치 테스트 도구 문구 동반 변경

## Impact

- **클라이언트 4타깃 문자열만**: iOS 폰 9파일, Android 폰 9파일, watchOS 1파일,
  Wear OS 1파일 — 전부 UI 문자열 리터럴 변경, 로직 무변경.
- **백엔드 1줄**: `main.py` 패배 유도 푸시 body — 플래그 OFF 다크 상태라 무배포 영향.
- **What's New 이미지 재제작 불필요**: `venting.jpg`에 "분풀이" 텍스트 미포함(펭귄+스탯만).
- **무변경**: API 경로(/venting/*), 푸시 kind=venting_loss·OPEN_VENTING, DB 테이블
  (venting_*), 딥링크(venting-debug), 워치 데이터레이어 경로, 코드 식별자 전부.
- 활성 change 문서 반영: `split-install-vs-update-onboarding`(가이드 스텝 카피),
  `use-real-game-for-venting-home-card`(홈카드 카피 인용).

## Non-Goals

- 코드 식별자·파일명·패키지(Venting*) 리네임.
- 스토어·마케팅 카피 갱신(리포 밖, 별도 트랙).
- 과거 openspec 문서·주석의 "분풀이(venting)" 표기 정리 — 내부 코드명으로 유지.

## Capabilities

### Modified Capabilities
- `venting-mode`: 사용자 노출 명칭을 "빠따존"으로 전환(장소=빠따존, 행위=분풀이 유지,
  💢는 단독 명칭 한정).
