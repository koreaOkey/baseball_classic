## Context

현재 모바일 상세 화면은 실시간 상태와 이벤트를 수신하지만, 경기 카드 클릭 후 보이는 화면이 단순 점수판과 이벤트 목록 중심이다. 레퍼런스는 야구장 필드, 이닝 탭, 현재 승부, 이벤트 흐름을 한 화면에서 스캔할 수 있는 구조를 요구한다.

이 변경은 모바일 Android와 iOS 화면에 한정한다. 두 플랫폼 모두 공통 백엔드의 state/events를 사용하며, 워치 앱은 기존 동기화 상태만 영향을 받는다.

## Goals / Non-Goals

**Goals:**

- Android와 iOS 상세 화면의 정보 구조를 맞춘다.
- BaseHaptic 디자인 시스템의 다크 팔레트, 타이포그래피, 스페이싱, 이벤트 색상 토큰을 사용한다.
- 현재 제공되는 백엔드 데이터 안에서 점수, 이닝, B/S/O, 루상 점유, 투수, 타자, 투구수, 최근 이벤트를 표현한다.
- 실시간 스트리밍, 재연결, 복구 pull 동작은 유지한다.
- 이벤트에 포함된 투수/타자 정보를 모바일 양쪽에서 파싱해 이벤트 카드에 표시한다.

**Non-Goals:**

- 선수 사진 표시.
- 실제 수비 위치/라인업, 주자 이름, 선수 상세 기록 API 구현.
- DB 마이그레이션.
- 워치 상세 화면 개편.
- 웹 화면 개편.

## Decisions

1. 모바일 상세 화면은 동일한 섹션 순서를 사용한다.
   - 순서: 상단 상태, 점수판, 필드 프리뷰, 이닝 탭, 현재 승부, 워치 동기화, 실시간 이벤트.
   - 이유: Android/iOS 사용자가 같은 정보 계층을 경험하고, QA 기준을 단순화할 수 있다.
   - 대안: 플랫폼별 완전히 다른 레이아웃을 유지할 수 있으나, 기능 차이가 커지고 유지보수 비용이 증가한다.

2. 필드 프리뷰는 현재 state 기반의 시각화로 제한한다.
   - 표현 대상은 투수, 타자, 루상 점유 여부다.
   - 이유: 현재 조회 API가 실제 수비 포지션, 라인업, 주자 이름을 제공하지 않는다.
   - 대안: 임시 더미 수비수를 표시할 수 있으나, 실시간 중계 화면에서 부정확한 정보가 신뢰도를 떨어뜨린다.

3. 이닝 탭은 현재 이닝 강조와 향후 확장을 위한 UI로 둔다.
   - 이유: 이벤트 응답에 이닝/초말 메타데이터가 없어 정확한 이닝별 필터링은 아직 불가능하다.
   - 대안: 이벤트 description을 파싱해 추정할 수 있으나, 크롤러 문구 변경에 취약하다.

4. 백엔드 변경은 이번 범위에서 제외하고 모바일 파싱만 보강한다.
   - 이벤트의 투수/타자 필드는 이미 응답에 포함되므로 양쪽 모바일 모델에서 파싱한다.
   - 이유: UI 목업 적용은 현재 API로 가능한 범위가 명확하며, 후속 백엔드 보강은 별도 변경으로 관리하는 편이 안전하다.

5. 배터리/네트워크 동작은 기존 방식을 유지한다.
   - 상세 UI는 추가 네트워크 요청을 만들지 않고 기존 state/events 스트림과 복구 pull을 재사용한다.
   - 이유: 경기 중 장시간 사용과 워치 동기화가 동시에 발생할 수 있어 불필요한 polling 증가를 피한다.

## Risks / Trade-offs

- [Risk] 필드 프리뷰가 실제 수비 포메이션이 아니라 현재 투수/타자/루상 상태만 보여준다. → 화면에는 제공 가능한 데이터만 표시하고, 라인업/수비 위치 API를 후속 과제로 분리한다.
- [Risk] 이닝 탭이 실제 이벤트 필터링처럼 보일 수 있다. → 현재는 현재 이닝 강조 중심으로 두고, 이벤트 메타데이터가 제공되면 필터링을 연결한다.
- [Risk] Android/iOS가 같은 레이아웃을 유지하지 못할 수 있다. → 섹션 순서와 표시 데이터 요구사항을 양 플랫폼 스펙에 동일하게 기록한다.
- [Risk] 추가 UI가 낮은 단말에서 스크롤 길이를 늘린다. → 첫 화면에 점수판과 필드 프리뷰가 먼저 보이도록 정보 우선순위를 둔다.

## Migration Plan

1. Android 상세 화면을 신규 섹션 구조로 교체한다.
2. Android 이벤트 모델에 투수/타자 파싱을 추가한다.
3. iOS 상세 화면을 동일한 섹션 구조로 교체한다.
4. iOS 이벤트 모델에 투수/타자 파싱을 추가한다.
5. Android/iOS 빌드 검증을 수행한다.

Rollback은 각 플랫폼 상세 화면 파일과 이벤트 모델 필드 변경을 이전 버전으로 되돌리는 방식으로 가능하다. DB와 백엔드 스키마 변경이 없어 데이터 마이그레이션은 필요 없다.
