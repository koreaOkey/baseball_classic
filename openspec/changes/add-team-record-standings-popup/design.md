## Context

현재 크롤러 디스패처는 네이버 스포츠 API의 시즌 팀 순위 데이터를 수집해 백엔드 인제스트 API로 전송하고, 백엔드는 `team_record`에 팀별 기록을 저장한다. 모바일 홈 화면은 선택한 팀의 순위와 승률만 조회하고 있으며, 전체 10개 팀 순위를 한 번에 보여주는 공개 목록 API와 팝업 UI는 없다.

이 변경은 기존 수집/저장 흐름을 유지하면서 모바일이 공통 백엔드 API를 통해 전체 순위 목록을 읽도록 한다. 앱이 네이버 API를 직접 호출하지 않게 하여 데이터 소스 변경, rate limit, 응답 필드 변경의 영향을 서버 쪽으로 제한한다.

## Goals / Non-Goals

**Goals:**

- 백엔드는 KBO 시즌별 전체 팀 기록을 순위순으로 반환한다.
- Android와 iOS 홈 화면은 팀 순위 아이콘을 제공하고, 탭하면 전체 팀 순위 팝업을 표시한다.
- 모바일은 기존 백엔드 기준 URL을 사용하고 네이버 스포츠 API를 직접 호출하지 않는다.
- 기존 `team_record` 테이블을 재사용하여 DB 마이그레이션 없이 배포한다.
- 워치 앱은 직접 UI 변경 없이 기존 동기화/라이브 기능 영향만 확인한다.

**Non-Goals:**

- 네이버 팀 순위 수집 주기나 수집 대상 API를 변경하지 않는다.
- 팀간 승패표, 선수 순위, 포스트시즌 순위는 이번 범위에 포함하지 않는다.
- 팝업에서 네이버 원격 팀 이미지 URL을 직접 렌더링하지 않는다.
- 워치 화면에 전체 순위 팝업을 추가하지 않는다.

## Decisions

- 전체 순위는 백엔드 목록 API로 제공한다.
  - 이유: Android/iOS가 동일한 계약을 사용하고, 네이버 API 변경 영향을 백엔드와 크롤러 경계에 한정할 수 있다.
  - 대안: 모바일에서 네이버 API 직접 호출. 구현은 빠르지만 외부 API 응답 형식과 네트워크 정책이 앱에 노출된다.

- 기존 `team_record` 테이블과 순위 인덱스를 재사용한다.
  - 이유: 현재 테이블은 `category_id`, `season_code`, `ranking` 인덱스를 이미 갖고 있어 전체 시즌 순위 조회에 적합하다.
  - 대안: 전체 순위 전용 테이블 추가. 중복 저장이 되며 현재 요구사항에는 과하다.

- 모바일 팝업은 목록형 하단 시트 또는 팝업으로 구성한다.
  - 이유: KBO 10개 팀을 표시해야 하므로 작은 경고 팝업보다 스크롤 가능한 목록 UI가 안정적이다.
  - 대안: 홈 카드 내부 확장. 메인 화면 정보 밀도가 높아지고 상단 아이콘의 빠른 조회 목적과 어긋난다.

- 팀 로고는 앱의 기존 팀 리소스 매핑을 우선 사용한다.
  - 이유: 백엔드 응답에 원격 이미지 URL을 추가하지 않아도 되고, 네트워크 실패 시에도 UI가 안정적이다.
  - 대안: 네이버 `teamImageUrl` 전달. 응답 스키마와 이미지 로딩 경로를 추가로 확장해야 한다.

## Risks / Trade-offs

- [Risk] 크롤러가 아직 팀 기록을 수집하지 않은 환경에서는 목록 API가 빈 목록을 반환할 수 있다. → 모바일은 빈 상태와 새로고침/재시도 affordance를 제공한다.
- [Risk] 경기 중에는 디스패처가 live crawler 실행 중 팀 기록 sync를 건너뛰므로 순위 반영이 지연될 수 있다. → 기존 수집 정책을 유지하고, 팝업에는 백엔드 `updatedAt` 기반 최신 반영 시각을 표시할 수 있게 한다.
- [Risk] iOS 구현 상태가 Android보다 덜 운영 중일 수 있다. → 동일 API와 동일 요구사항으로 구현하되, iOS 빌드 가능 여부를 별도 검증 태스크로 둔다.
- [Risk] 워치 앱에는 직접 기능이 없지만 공통 데이터 모델 변경이 간접 영향을 줄 수 있다. → 워치 관련 코드 경로가 새 API를 참조하지 않는지 확인한다.

## Migration Plan

- DB 마이그레이션은 수행하지 않는다.
- 백엔드 목록 API를 먼저 배포한다.
- Android/iOS 앱에서 새 API를 호출하도록 배포한다.
- 롤백 시 모바일 아이콘 클릭 진입점과 repository 호출만 제거하면 기존 선택 팀 기록 조회는 유지된다.
