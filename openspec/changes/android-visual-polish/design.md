## Context

Android 모바일 앱은 현재 운영 중인 주 플랫폼이며, iOS 화면과 같은 디자인 토큰과 정보 구조를 공유한다. 다만 Android는 시스템 바와 하단 내비게이션의 기본 Material 인상, 홈 카드의 높은 정보 밀도, 라이브 상세 점수판의 고정 치수 때문에 같은 콘텐츠라도 iOS보다 거칠고 답답하게 보인다.

이번 변경은 모바일 Android UI와 Android 스토어 스크린샷에 한정한다. 백엔드 API, DB, 크롤러, iOS 앱, Watch Android/iOS 동기화 로직은 변경하지 않는다. 배터리와 네트워크 동작에도 영향을 주지 않도록 렌더링 스타일과 레이아웃 조정만 수행한다.

## Goals / Non-Goals

**Goals:**
- Android 시스템 바가 앱의 다크 팔레트와 자연스럽게 이어지게 한다.
- Android 하단 내비게이션을 더 낮은 밀도와 조용한 강조로 조정한다.
- Android 홈 경기 카드의 상태, 점수, 액션 영역을 더 정돈된 계층으로 보이게 한다.
- Android 라이브 상세 점수판이 좁은 화면에서도 균형 있게 보이도록 고정 치수와 텍스트 밀도를 줄인다.
- Android Play Store 홈 스크린샷이 실제 앱 개선 방향과 같은 시각 언어를 반영하게 한다.

**Non-Goals:**
- iOS 화면 리디자인.
- Wear OS 또는 Apple Watch 화면 변경.
- 야구 데이터 모델, 실시간 스트림, 알림 데이터 계약 변경.
- 새 외부 의존성 추가.
- DB 마이그레이션.

## Decisions

1. Android 시스템 바는 다크 전용 마감으로 정리한다.
   - 상태바와 내비게이션바를 앱 배경색에 맞추고, 시스템 아이콘은 다크 배경에 맞는 밝은 아이콘으로 유지한다.
   - 대안으로 전체 edge-to-edge 레이아웃을 모든 화면에 강제할 수 있으나, 기존 Scaffold와 광고 배너/하단 내비게이션 간섭 위험이 있어 이번 범위에서는 시스템 바 색과 contrast 마감에 집중한다.

2. 하단 내비게이션은 Material 기본 인상을 낮춘다.
   - 높은 elevation과 큰 indicator보다 배경, 토큰 폰트, 낮은 alpha indicator로 현재 앱의 조용한 다크 스포츠 톤에 맞춘다.
   - 대안으로 완전 커스텀 navigation bar를 만들 수 있으나, 접근성과 선택 상태 처리를 다시 구현해야 하므로 기존 컴포넌트 안에서 조정한다.

3. 홈 경기 카드는 콘텐츠 계층을 줄이고 액션 row를 보조 정보로 낮춘다.
   - 경기 상태/팀/점수는 카드의 주 정보로 유지하고, 잠금화면/Watch 액션은 작은 컨트롤처럼 보이게 한다.
   - 대안으로 홈 카드 액션을 제거할 수 있으나, 기존 진입점을 잃게 되므로 시각 밀도만 줄인다.

4. 라이브 상세 점수판은 고정 중앙 폭과 대형 텍스트를 완화한다.
   - 팀명, 점수, 중앙 B/S/O 영역이 서로 밀리지 않도록 중앙 블록과 점수 타이포를 보정한다.
   - 대안으로 상세 화면 전체 구조를 다시 바꿀 수 있으나, `redesign-live-game-detail-screen` change가 이미 완료한 정보 구조를 유지한다.

5. Android 스토어 스크린샷은 실제 앱과 같은 방향으로 별도 보정한다.
   - Android용 렌더러의 카드 밀도, 상태 문구, 한글 팀명, 상단/하단 여백을 Android 개선 결과에 맞춘다.
   - 대안으로 실제 기기 캡처만 사용할 수 있으나, 현재 저장소는 React 렌더러 기반 산출물을 유지하고 있어 렌더러도 함께 보정한다.

## Risks / Trade-offs

- [Risk] Android와 iOS가 픽셀 단위로 달라질 수 있다. → 동일한 정보 구조와 토큰 계열은 유지하고 Android 플랫폼 마감만 보정한다.
- [Risk] 하단 내비게이션 조정이 기존 사용자에게 낯설 수 있다. → 탭 구성과 선택 동작은 바꾸지 않고 색/밀도만 낮춘다.
- [Risk] 스크린샷 렌더러와 실제 앱이 다시 어긋날 수 있다. → 이번 변경에서 HomeScreen 앱 구현과 Android 홈 스크린샷을 같은 방향으로 조정한다.
- [Risk] 시각 개선은 자동 테스트로 완전히 검증하기 어렵다. → Android 컴파일과 스크린샷 렌더 명령으로 최소 회귀를 확인하고, 최종 비교는 산출 이미지로 확인한다.

## Migration Plan

1. Android theme/system bar 설정을 조정한다.
2. Android 하단 내비게이션과 홈 카드 컴포넌트를 조정한다.
3. Android 라이브 상세 점수판의 밀도를 낮춘다.
4. Android Play Store 홈 스크린샷 렌더러를 보정한다.
5. Android 빌드와 스크린샷 렌더를 검증한다.

Rollback은 이번 change에서 수정한 Android UI/theme/screenshot 파일을 이전 커밋으로 되돌리면 된다. 데이터 마이그레이션과 서버 배포는 필요 없다.

## Open Questions

- Android 전체 스토어 스크린샷 4장을 모두 이번 범위에서 보정할지, 홈 화면부터 단계적으로 보정할지 후속 결정이 필요하다.
- 실제 기기 캡처 기반 QA를 추가할지, 현재 React 렌더러 중심의 QA를 유지할지 후속 작업에서 정할 수 있다.
