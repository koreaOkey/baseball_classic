## Context

Android 홈 화면은 백엔드 `/games` 응답으로 오늘 경기와 응원팀의 다가오는 경기를 표시한다. 현재 경기 데이터에는 구장 기반 날씨 정보가 없지만, 백엔드는 이미 KBO 구장 메타데이터와 홈팀 기반 구장 매핑을 보유하고 있다. 날씨 API 키는 모바일 앱에 포함하면 안 되므로 백엔드가 공공데이터포털 기상청 단기예보 API를 프록시하고 캐시한다.

## Goals / Non-Goals

**Goals:**
- 경기 시작 시점의 예보 요약을 홈 경기 카드와 다가오는 경기 카드에 표시한다.
- 오늘 경기 카드의 예보 요약을 탭하면 해당 구장의 오늘 시간별 예보를 표시한다.
- 예정/진행 중 경기에는 경기 시작 예보를 표시하고, 종료 경기에는 표시하지 않는다.
- 날씨 API 실패나 키 미설정이 경기 목록 조회 실패로 번지지 않게 한다.

**Non-Goals:**
- watchOS, Wear OS 화면에 날씨 UI를 추가하지 않는다.
- 날씨 데이터를 DB에 영구 저장하지 않는다.
- 실시간 현재 날씨, 우천취소 예측, 알림 발송을 구현하지 않는다.

## Decisions

1. 백엔드 프록시 방식으로 연동한다.
   - 이유: 공공데이터 API 키 보호, 호출량 제어, Redis 캐싱, 실패 폴백을 백엔드에서 통제할 수 있다.
   - 대안: Android 앱 직접 호출은 키 노출과 플랫폼별 중복 구현 때문에 제외한다.

2. `/games` 응답에는 optional weather 요약만 추가한다.
   - 이유: 홈 목록은 빠르게 렌더링되어야 하며, 시간별 전체 예보는 사용자가 탭할 때만 필요하다.
   - 대안: 모든 시간별 예보를 목록 응답에 포함하면 응답 크기와 외부 API 호출 부담이 커진다.

3. 시간별 예보는 경기별 상세 엔드포인트로 제공한다.
   - 이유: 오늘 경기 카드에서만 바텀시트가 필요하며, 기존 홈 화면의 순위/일정 바텀시트 패턴과 맞다.
   - 진행 중 경기의 목록 응답에 `weather` 요약이 누락된 경우에도 같은 상세 예보의 경기 시작 시간대 정보를 사용해 홈 카드 요약을 유지한다.

4. 구장 매핑은 홈팀 기준으로 계산한다.
   - 이유: KBO 일정에서 홈팀이 경기장을 결정하며, 기존 구장 메타데이터도 홈팀 코드 기준으로 구성되어 있다.
   - 돔구장은 외부 날씨 대신 “날씨 영향 적음” 상태로 반환한다.

5. 모바일/워치 플랫폼 차이는 응답 호환성으로 관리한다.
   - Android/iOS 모바일 홈 화면은 경기 시작 예보 요약과 오늘 시간별 예보 상세를 표시한다.
   - Wear OS와 watchOS는 경기 목록 카드 날씨를 표시하지 않는다.

## Risks / Trade-offs

- [Risk] 외부 날씨 API 장애 또는 키 미설정 → `/games`는 날씨 없이 정상 응답하고, 상세 조회는 재시도 가능한 오류 상태를 반환한다.
- [Risk] 예보 발표 시각과 경기 시작 시각이 맞지 않음 → 경기 시작 시간과 가장 가까운 예보 시간대를 선택하고 `N시 기준`으로 명시한다.
- [Risk] 홈 목록 조회가 느려질 수 있음 → 구장/날짜/시간대 단위 캐시를 사용하고, 날씨 조회 실패는 목록 응답을 차단하지 않는다.
- [Risk] 다가오는 경기의 예보 가능 범위가 제한됨 → 예보 범위 밖 일정은 날씨 컴포넌트를 숨긴다.
