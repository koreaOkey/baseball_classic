## ADDED Requirements

### Requirement: 애니메이션 프레임 메모리 상한
watchOS 이벤트 애니메이션은 프레임을 시스템 이미지 캐시에 누적하지 않아야 한다(SHALL NOT). 재생 시점에 소수의 프레임만 메모리에 유지한다.

#### Scenario: 애니메이션 재생 후 메모리 회수
- **GIVEN** 홈런 애니메이션(101 프레임)이 재생 완료됐을 때
- **WHEN** 다음 이벤트가 오기 전 메모리를 확인하면
- **THEN** 재생에 사용된 프레임 이미지는 해제되어 있다

### Requirement: 경기 시작 감지 폴링 최소화
워치 독립 폴링은 대상 경기를 특정한 후에는 단일 경기 조회로 상태를 확인해야 하며(SHALL), 씬이 비활성일 때 폴링하지 않아야 한다(SHALL NOT).

#### Scenario: gameId 확보 후 단건 폴링
- **GIVEN** 하루 일정 조회로 내 팀 경기 gameId를 확보했을 때
- **WHEN** 30초 주기 폴링이 실행되면
- **THEN** 워치는 해당 경기의 단건 조회로 상태를 확인한다

#### Scenario: 씬 비활성 시 폴링 중단
- **GIVEN** 경기 시작 전 폴링이 동작 중일 때
- **WHEN** 앱 씬이 비활성/백그라운드로 전환되면
- **THEN** 폴링을 중단하고, 다시 활성화되면 즉시 조회로 재개한다

### Requirement: 동일 상태 재할당에 의한 렌더 무효화 금지
라이브 데이터 수신 시 관찰 대상 상태는 값이 실제로 변경된 경우에만 갱신해야 한다(SHALL). 햅틱·이벤트 처리는 이 최적화와 무관하게 항상 수행된다.

#### Scenario: 내용이 같은 game_data 수신
- **GIVEN** 직전과 동일한 내용의 game_data 메시지가 도착했을 때
- **WHEN** 워치가 메시지를 처리하면
- **THEN** @Published 상태를 재할당하지 않아 뷰 무효화가 발생하지 않는다
- **AND** 이벤트·햅틱 판정은 정상 수행된다
